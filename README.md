# 国会 法律案トラッカー（個人運営・非公式）

国会に提出された法律案の審議状況を自動で整理し、参考情報を付して表示する個人運営のサイト。
公式の情報ではなく、内容の正確性は保証しない。掲載内容は必ず一次資料で確認すること。

## 実装している要素

- **ダッシュボード**：ステータス別の件数集計
- **フィルタ**：ステータス／提出区分（閣法・衆法・参法）／所管省庁／キーワード（クライアント側で即時絞り込み）
- **法案カード**：ステータスバッジ・議案番号・所管・成立確度・タグ
- **詳細ドロワー**：
  - **概要（AI生成）** … 提案理由・趣旨をもとにした要約（「要確認」注記付き）
  - **審議タイムライン** … 提出→衆委→衆本→参委→参本→公布。現在地・可決・継続を色分け
  - **参考情報（信頼度別）** … Tier1 一次/準一次 → Tier2 立法補佐機関 → Tier3 シンクタンク → Tier4 専門家解説。自動紐付けの確信度バー付き

## ファイル

- `index.html` … UI・描画ロジック（依存ライブラリなし。`data_collected.js` を読み込む）
- `collect.py` … 収集スクリプト（参議院 議案情報をスクレイピング → 正規化JSON）。
  あわせて会議録検索API（件名＝正式名称×会期×付託委員会）で該当**会議録の一覧**を取得し、
  各会議を `第N回 院 委員会 第n号` → `#/detail?minId=<issueID>` の個別リンクとして付与（0件は非掲載）
- `enrich.py` … 補強モジュール（内閣法制局・衆議院から 所管省庁・提出理由 を付与）
- `sessions.yaml` / `sessions.py` … 会期メタデータ（召集日・閉会日・内閣法制局の一覧ID）とその読み込み。
  参議院サイトだけでは「審議中」と「閉会により審査未了」を区別できないため、閉会日を外部情報として持つ
- `sources.yaml` / `crawl.py` … 参考リンクのソース台帳とクローラ（→ `refs.db`）
- `aliases.yaml` … 法案の通称・関連キーワード辞書（審議会等との紐付けの鍵）
- `match_refs.py` … 参考文書を法案に紐付け（語彙＋所管＋趣旨＋意味類似でスコア化）
- `llm_gate.py` … 弱い候補をLLMで関連性検証（任意・要APIキー）
- `linkcheck.py` … 参考リンクの死活チェック（＋Wayback提案）
- `run_all.bat` … 週次高品質パイプライン（Ollama要約・PDF抽出・e5照合を含む）一括実行
- `run_weekly.ps1` … 月曜のローカル週次処理を安全に更新・検証・commit/pushするラッパー
- `tag.py` … 検索用タグ付与（ステータス／所管／法令名／主題キーワード）
- `ingest_submission.py` / `merge_submissions.py` … 参考情報の提供（Issue）処理と掲載反映
- `apply_suppressions.py` … 承認済みの取り下げ依頼を反映して該当refを除外（`suppressions.json`）
- `requirements-core.txt` … 日次更新・Issue処理用の依存パッケージ
- `requirements-semantic.txt` … 意味検索を含む全機能用（`requirements.txt` は後方互換の入口）
- `requirements-dev.txt` … テストなど開発用の依存パッケージ
- `DEPLOY.md` / `.github/workflows/` … 公開方法・CI自動更新・情報提供Issue処理
- `bills.json` / `data_collected.js` … パイプラインの出力（`window.BILLS` に直接流用可）
- `refs.db` … 収集した参考文書のインデックス（SQLite）

## 収集パイプラインの使い方

```
python collect.py --diet 221                      # 全法律案（省庁・提出理由も補完）
python collect.py --diet 221 --only 31,32,33,13 --output tmp/sample.json --allow-partial-output  # 安全な部分実行
python collect.py --diet 221 --no-enrich          # 参議院データのみ（高速）
python collect.py --diet 221 --llm-summary        # 提出理由をLLMで3行要約（既定はローカルOllama）
python collect.py --diet 222 --clb-id <id>        # 新会期は内閣法制局の一覧IDを指定
```

処理段階:
1. **収集**（`collect.py`）… 参議院 議案明細（衆参両院の経過を1ページに含む）を解析
2. **正規化** … 先議区分で院順を決め、提出→委員会→本会議→公布のタイムラインを合成。
   公布日/継続/未了/否決の有無と会期の開閉から ステータス
   （成立・審議中・継続審査・審査未了・廃案）を判定（`sessions.py` / `sessions.yaml`）
3. **補強**（`enrich.py`）… 概要・所管・参考リンクを付与
   - **閣法**: 内閣法制局の一覧から **主管省庁**、詳細ページから **提出理由**
   - **衆法・参法**（議員立法）: 衆議院の提出法律案本文から末尾の **「理由」** を抽出
   - 概要は `--llm-summary` で**ローカルLLM(Ollama)が自分の言葉に要約**（著作権配慮で原文非転載、
     `summaries.json` にキャッシュ）。モデルは `OLLAMA_MODEL`（既定 gemma4:12b）。フラグ無しは原文
   - 所管省庁ページ・内閣法制局詳細ページ・衆議院本文を参考リンクに追加

## サイトでの表示

`index.html` は収集パイプラインの出力 `data_collected.js` を読み込んで表示する（単一データ源）。

## 参考リンクの収集

設計は `DESIGN_refs.md`。収集（クロール）と紐付け（マッチング）を分離している。

```
python crawl.py            # sources.yaml を巡回し refs.db に文書を蓄積（845件）
python crawl.py --stats    # 蓄積状況
python match_refs.py       # refs.db の文書を bills.json に紐付け → data_collected.js
python match_refs.py --dry # 書き込まずレポートのみ
python match_refs.py --no-semantic  # 意味類似を無効化
python match_refs.py --llm-gate     # 弱い候補をLLMで関連性検証（要 ANTHROPIC_API_KEY）
python merge_submissions.py         # 承認済みユーザー提供情報（Tier4）を反映
python apply_suppressions.py        # 承認済み取り下げ依頼を反映（除外）
python tag.py                       # 検索用タグ付与
run_all.bat                # Ollama要約→PDF抽出→e5照合→提供/取り下げ反映→タグ→死活（週次高品質）
```

実行順は `collect.py` → `crawl.py` → `match_refs.py` → `merge_submissions.py` →
`apply_suppressions.py` → `tag.py`（`run_all.bat` / `.github/workflows/update.yml` と同一）。

公開方法（GitHub Pages + Actions 等）は `DEPLOY.md` を参照。

### 会期の管理（sessions.yaml）

会期の開閉は `sessions.yaml` で管理する。参議院の議案情報は、審査未了の議案を
`議決・継続結果 = 未了` と記録するが、**委員会付託前の議案は提出日以外すべて空欄**になる。
つまりサイトのデータだけでは「審議中」と「閉会により審査未了」を区別できず、
閉会日という外部情報が要る。

```yaml
sessions:
  - diet: 221
    name: 特別会
    from: "2026-02-18"
    to: "2026-07-25"        # 閉会済み。会期中は null
    clb_id: "5144"          # 内閣法制局 一覧ページID
```

```
python sessions.py status       # 会期一覧と開閉状態
python sessions.py latest       # 最新の回次
python sessions.py should-run   # CI用ゲート（run=true/false）
```

**会期が変わったときの手順（2箇所だけ）**

1. `sessions.yaml` に新しい会期を追記する（`to: null`）。同時に、閉会した会期の `to` に閉会日を入れる。
2. `.github/workflows/update.yml` の `env.DIET` を新しい会期番号に更新する。

`run_all.bat`（週次ローカル処理）は `python sessions.py latest` で対象会期を自動取得するので手当て不要。
`sessions.yaml` に未登録の会期を `--diet` に指定すると `collect.py` が警告を出す（登録忘れの検知）。
`clb_id` は `sessions.yaml` が優先され、未設定なら `enrich.py` の `CLB_INDEX`（後方互換）を見る。

`bills.json` は複数会期を保持し、`collect.py --diet N` は **N の会期だけを差し替えて他会期は残す**。
件数減少・会議録リンク減少の安全ガードも同一会期内で比較する。

### ステータスの取りうる値

`成立` / `審議中` / `継続審査` / `審査未了` / `廃案` の5種。判定順序は次のとおり。

1. 公布日あり → **成立**
2. 両院の本会議で可決（修正議決を含む） → **成立**（公布待ち）
3. 「継続」を含む → **継続審査**
4. 「未了」を含む → **審査未了**（参議院サイトの明示的な記録）
5. 「否決」「廃案」を含む → **廃案**
6. 上記以外で会期が閉会済み → **審査未了**（付託の有無で詳細文言を分ける）
7. それ以外 → **審議中**

6 には猶予がある。閉会直後は参議院サイトの反映が追いつかないため、閉会日から7日間は
判定を保留して「審議中」のままにする（`sessions.CLOSE_GRACE_DAYS`）。

### 自動更新の運用

- GitHub Actionsの軽量更新は **JST火〜日 01:01頃** に起動する。
- **閉会中は週1回（JST土曜）だけ**フルパイプラインを走らせ、それ以外の日はスキップする。
  判定は `sessions.py should-run`（開会中の会期があるか）で行い、cron は日次のまま触らない。
  会期が再開すれば `sessions.yaml` の更新だけで自動的に日次運用へ戻る。
  `workflow_dispatch` による手動実行は、閉会中でも常にフル実行する。
  閉会中でも `crawl.py` による参考文書（審議会・NDL資料）の収集には価値があるため、週次実行は省略しない。
- **月曜 00:00** はローカルWindowsの `run_weekly.ps1` が担当し、Ollama要約、PDF要旨抽出、
  multilingual-e5による意味類似を含む高品質処理を公開する。これにより全体では毎日更新となる。
- ローカル処理には、起動済みのOllama、`OLLAMA_MODEL`（未指定時 `gemma4:12b`）の導入、
  `requirements-semantic.txt` と `requirements-dev.txt` の依存関係、GitHubへのpush権限が必要。
  Ollamaまたはモデルを利用できない場合は、品質を落として続行せず失敗する。
- タスクスケジューラの操作例は、プログラムを `powershell.exe`、引数を
  `-NoProfile -ExecutionPolicy Bypass -File "D:\py\bill-tracker\run_weekly.ps1"` とし、毎週月曜00:00に設定する。
  開始フォルダーは `D:\py\bill-tracker` とする。

週次スクリプトは開始時の未コミット変更と処理中のリモート更新を検出すると、安全のためcommit/pushせず
非ゼロで終了する。ログはUTF-8で `build.log` に保存し、commit対象は公開用生成物だけに限定する。

## 参考情報の提供（ユーザー投稿）

各法案の詳細から「参考情報を提供する」→ 事前入力済みの GitHub Issue（`submit-ref.yml`）で
**対象法案＋URL**（NDLサーチ/CiNiiの書誌、記事URL等）を投稿。以後は自動：

1. Issue投稿/編集 → `ingest_submission.py` が **書誌メタ（og/citation/JSON-LD/title）を抽出**し、
   `match_refs` の語彙＋趣旨キーワードで **関連度を推定** → 結果をIssueにコメント＋`needs-review`。
   （NDLデジコレ等のJS描画ページはタイトル自動取得不可→コメントで手動補完）
2. メンテナが内容を確認し `approved` ラベル → `submissions.json` に取り込み、
   `merge_submissions.py` がサイトデータへ「提供情報」(Tier4)として反映、Issueをクローズ。
3. 日次・週次ビルドは match→**merge_submissions**→**apply_suppressions**→tag の順で、
   再生成後も提供情報の掲載・取り下げ依頼の除外を維持。

| Tier | ソース | 取得方式 | 件数 |

| 2 立法補佐機関 | 国会図書館「レファレンス」 | 年次アーカイブ＋RSS | 113 |
| 2 立法補佐機関 | 参議院「立法と調査」 | HTML（号→記事） | 162 |
| 1 審議会・検討会 | 9省庁の審議会・研究会（総務/厚労/国交/金融/農水/財務/法務/環境/警察） | HTML一覧＋個別ページ | 約1,000 |

本文は保存せずタイトル・URL・発行日のみ（著作権配慮）。NDLはpidで重複排除。
国会図書館は**2024〜2026年**を巡回（法案は提出の1〜2年前から論点化されるため広めに）。
審議会は所管省庁が一致する会議のみ照合対象とし、誤マッチを抑制（文科省403/経産省・内閣府は未対応）。

### マッチャ（`match_refs.py` / `aliases.yaml`）

4系統でスコア化し Tier別閾値で採用（DESIGN_refs.md §5）:
- **語彙一致**（立法補佐機関）… 法案名の部分一致＋文字3-gram。「立法と調査」は
  副題に法案名を含むため高精度。例: 防衛省設置法/太陽電池廃棄物/金融商品取引法 = 77〜92%。
- **趣旨キーワード**（部分改正法に有効）… `summary`(提出理由)から内容語を抽出し、
  **コーパス文書頻度(DF)で希少語だけ採用**（IDF的フィルタ）して照合。件名が汎用
  （「民法等の一部を改正…」）でも趣旨の主題語で拾える。例: 成年後見/暗号資産/資金決済/
  郵政事業/プラスチック/災害対策基本法 等。
- **所管×通称**（審議会・検討会）… 所管省庁が一致する会議のみ対象（precision確保）に、
  `aliases.yaml` の通称キーワード＋趣旨キーワードで紐付け。会議ページは h1＋WG名＋報告書名を
  内容語として収録するため、抽象的な会議名でも拾える。例: ドローン法案→警察庁「違法な
  ドローン飛行対策に関する検討会」、携帯本人確認法→総務省「不適正利用対策WG/利用者情報WG」、
  郵便法→総務省「郵便料金政策委員会」= 82%。
- **意味類似**（プラガブル層）… `multilingual-e5` が「法案の趣旨 × 文書の要旨」の長文比較で
  類似度を算出。**要旨は crawl.py が立法と調査・NDLのPDF冒頭から抽出**（refs.db の abstract 列。
  CI では `--no-abstracts` でスキップ）。同義語（太陽光パネル↔太陽電池 等）を橋渡しできる。
  候補は法案ごと top-3（ゲート無効時は top-1）＋平均からのマージン要件。`--no-semantic` で無効化可。
- **LLM関連判定ゲート**（`llm_gate.py`）… ローカルLLM(Ollama, gemma4) → Anthropic の順で
  自動選択し、**利用可能なら既定で有効**（`--no-llm-gate` で無効化）。弱い候補（意味類似・
  趣旨KW・語彙類似・審議会の関連語一致）を「関連する/しない＋一文根拠」で検証し、
  根拠は UI の ⚙ 行に表示。判定は `gate_cache.json` にキャッシュ。
  例: 郵便法→「モバイル市場の競争環境に関する研究会」（趣旨KW「競争環境」由来の混入）を除外、
  ドローン検討会・郵便料金政策委員会・不適正利用WG は維持。
- **審議会の開催時期検証** … 候補になった会議ページのみ取得して最新開催月を抽出
  （`meeting_dates.json` にキャッシュ）し、提出の3年前〜6か月後の窓で古い会議を除外。
- **却下の還流** … `suppressions.json`（承認済み取り下げ）の (法案,URL) は候補生成から除外。

> 既知の限界: TF-IDFは文字の重なりしか見ないため、真の同義
> （太陽光パネル↔太陽電池 / 本人確認↔ガバナンス / ドローン↔小型無人機）は橋渡しできない。
> 当面は `aliases.yaml` が同義を吸収し、本格対応は `sentence-transformers` 導入で
> `build_semantic()` が自動的に e5 へ切り替わる（コード変更不要）。

## 本番化に向けたデータパイプライン対応

サイトデータ `data_collected.js` は、以下の自動収集パイプラインで生成している。

```
[収集]  参議院 議案情報 / 衆議院 審査経過（HTMLスクレイピング）
        国会会議録検索 API（JSON）… 質疑・論点
        内閣法制局 / 所管省庁 … 提案理由・要綱・新旧対照
            │  日次軽量更新／月曜ローカル週次高品質更新
[正規化] イベント列 → ステートマシンで現在ステータス・成立確度を算出
[付与]   所管省庁×時期×テーマで審議会・検討会を逆引き
        主要シンクタンク／法律事務所のRSS・更新ページをインデックス化
        → 法案要約のベクトルとセマンティック検索で候補抽出＋確信度スコア
        → Tier1は自動採用、Tier3-4は「候補」表示
[配信]   静的サイト生成（GitHub Pages）。index.html が data_collected.js を読み込む
```

### 確信度と表示の出し分け（信頼性の肝）

- Tier1（議案情報・会議録・所管省庁・国会図書館）＝法案単位で紐付くため**自動採用**
- Tier3-4（シンクタンク・法律事務所）＝**候補＋確信度**で提示し、本文転載はせずリンク＋短い要約のみ
- AI生成物には必ず「要確認」注記と一次資料リンクを併記
